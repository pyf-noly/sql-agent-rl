# P6 执行手册：在 BIRD 上跑 SFT → GRPO（单轮）→ 评测

> 前置：`docs/p6_bird_feasibility.md`（本地实测的可行性、成本、风险）。
> 本文只写"上卡之后逐条敲什么"，每一步都有验收标准，不达标不要往下走。

---

## 0. 这张卡要干什么（一眼看懂）

```
租 4090-24G（这次是新区的新实例）
  ├─ Step 0：传 bundle（5MB）→ 装三个包 → 下模型 7.6GB → 下 BIRD（落盘 ~10GB）
  ├─ Step 1：装配（bundle 已带 data/bird，可跳过）
  ├─ Step 2：SFT（BIRD 上从零训）
  ├─ Step 3：评测 dev300 拿 SFT 起点
  ├─ Step 4：GRPO 单轮、G=4、200 步、库级留出
  └─ Step 5：全量评测 + 打包 → 关机
```

**预算**：新机器从零要多花 ~30~40 分钟下载，合计 **5~7 小时 / ¥13~18**。
若某一步报错，**先关机再排查**，不要在计费的机器上调代码。

## Step 1 · 数据装配（已有 `data/bird` 可跳过）

打包里已经带了装配产物（`data/bird/*.jsonl`），**新机器不用重跑**。
只有当你改了切分规则、或者想换 holdout 数量时才需要：

```bash
python scripts/prepare_bird.py \
    --dev-dir data/raw/bird/dev_20240627 \
    --train-dir data/raw/bird/train \
    --out-dir data/bird --holdout-dbs 15 --sft-limit 4000

```

**验收**：
- `data/bird/meta.json` 的 `checks.ok = true`；
- `sft_rl_prompt_overlap = 0`、`train_dev_db_overlap = 0`；
- `sft_train.jsonl` 3920 条 / `sft_val.jsonl` 80 条 / `rl_train.jsonl` 1976 条；

**注意磁盘**：全量解压 train 要 **30.2GB**（zip 里还套了一层 zip）；

## Step 2 · SFT（约 45~70 min）

```bash
# 从零训（推荐：本地实测 Spider-SFT 在 BIRD 上零迁移，同题配对只 +1.4pp）
python -m training.train_sft --config configs/train/sft_bird.json

# 不推荐接 P4 的 Spider adapter 续训——实测没有收益，还会引入分布切换：
# python -m training.train_sft --config configs/train/sft_bird.json \
#     --init-adapter runs/sft_db110/adapter
```

**验收**：
- `n_mismatch = 0`（mask 边界没错）；
- `val_loss` 明显下降（BIRD 比 Spider 难，绝对值会更高，0.15 以内都算正常）；
- 显存峰值 < 22G；`max_len=3072` 下 batch=2 应该吃得下。

## Step 3 · 先评一次 SFT 的 BIRD 起点（约 20 min）

```bash
python scripts/run_baseline.py --dataset bird --backend hf --turns 1 \
    --model-path /root/autodl-tmp/qwen3-4b \
    --adapter runs/sft_bird/adapter \
    --timeout 10 --limit 300 --max-new-tokens 320 --tag bird_sft_t1_300
```

**判读**（关键，决定要不要继续）：
- **SFT ≤ 12%**：SFT 没学到 BIRD 的 schema/取值习惯 → 先别做 RL，回来查数据或加大 SFT；
- **12% ~ 55%**：最佳区间，继续 GRPO；
- **≥ 70%**：BIRD 对 4B 也快饱和了 → 换更难的分片（hard-only）或改做 P6 的机制分析。

## Step 4 · GRPO（约 90~120 min）

```bash
python -m training.train_grpo --config configs/train/grpo_bird.json \
    --init-adapter runs/sft_bird/adapter --model /root/autodl-tmp/qwen3-4b
```

**要盯的四个数**（每个都对应 P4/P5 踩过的坑）：

| 指标 | 期望 | 不达标说明什么 |
|---|---|---|
| `mask_mismatch` | 恒 0 | chat 模板/mask 算错了 |
| `ratio_mean` | 恒 1.0 | 一个 inner epoch、旧策略=新策略，应恒 1 |
| `zero_var_ratio` | **< 0.6** | 若仍 >0.8，说明 BIRD 没带来方差，停下来看 `reward_mean` |
| 显存峰值 | < 22G | micro_batch 调 1 |

**和 P5 的关键差别**：BIRD 的训练 prompt 是**留出库**（SFT 没见过的 15 个库），
单轮准确率预期 20~40%，所以 `zero_var_ratio` 应该从 P5 的 0.81~0.87 降到 0.4~0.6。
**如果这一项没有下降，说明"换数据"这个假设是错的**——那就要回头重估整个 P6，而不是继续调参。

## Step 5 · 全量评测 + 打包（约 35 min）
```bash
python scripts/run_baseline.py --dataset bird --backend hf --turns 1 \
    --model-path /root/autodl-tmp/qwen3-4b \
    --adapter runs/grpo_bird/adapter \
    --timeout 10 --max-new-tokens 320 --tag bird_grpo_t1

python scripts/run_baseline.py --dataset bird --backend hf --turns 3 \
    --model-path /root/autodl-tmp/qwen3-4b \
    --adapter runs/grpo_bird/adapter --until-correct \
    --timeout 10 --max-new-tokens 320 --tag bird_grpo_t3

python scripts/compare_results.py results/baseline_bird_*.json

# 打包（注意：不要打数据库，只打结果与 adapter）
python scripts/pack_bundle.py --out dist/p6bird_bundle.zip
```

**验收表长这样**（base 与 Spider-SFT 两行是本地 4-bit 实测，可直接对照）：

| 设置 | t1 EA（官方口径） | easy | medium | hard | zero_var |
|---|---|---|---|---|---|
| base 4B（本地 4-bit，512 条抽样） | 49.8% | 57% | 40% | 32% | — |
| Spider-SFT 零样本迁移（220 条） | 40.9% | 49% | 26% | 33% | — |
| BIRD-SFT | ? | | | | — |
| BIRD-SFT + GRPO | ? | | | | <0.6 |

**判读**：
- GRPO 比 SFT 高 **≥ +3pp**：成立，可以做 P6 轮级信用分配；
- **+1~3pp**：和 P5 一个量级，需要第 2 个 seed 才能下结论；
- **≈0 或为负**：先看 zero_var 是否真的降了；降了还没提升，说明奖励/超参有问题，别急着加实验。

## Step 7 · P6 核心：多轮 SFT + 轮级优势（第二次开机做）

> 前置：`docs/p6_results.md` §7。第一次实验（单轮）证明了两件事：
> **200 步单轮 GRPO 没提升**、**模型不会用反馈（三轮只救回 5.9% 错题）**。
> 所以第二次开机先补多轮能力，再上轮级优势。

### 7.1 本地产出的数据（已在 bundle 里，不用在机器上重跑）

| 文件 | 内容 |
|---|---|
| `data/bird_p6/sft_train.jsonl` | 3919 条：单轮 gold 2786 + **多轮修复 1133**（29%） |
| `data/bird/repairs_synth.jsonl` | 多轮修复的原始轨迹（可复查） |

本机生成命令（已跑过，重跑约 10 min，不花钱）：

```bash
python scripts/make_repair_synthetic.py --limit 1200
python scripts/merge_p6_sft.py
```

### 7.2 多轮 SFT（约 50 min）

```bash
python -m training.train_sft --config configs/train/sft_bird_p6.json
```

**验收**：`n_mismatch=0`；val_loss 应低于单轮 SFT 的 0.1428 附近水平；
`data/bird_p6/meta.json` 里 `turns_hist` 应该是 `{"1": 2786, "2": 1133}`。

### 7.3 三轮 GRPO + 轮级优势（约 90~120 min）

```bash
python -m training.train_grpo --config configs/train/grpo_bird_turn.json \
    --init-adapter runs/sft_bird_p6/adapter --model /root/autodl-tmp/qwen3-4b
```

**要盯的数**：

| 指标 | 期望 | 说明 |
|---|---|---|
| `turns_mean` | **> 1.5** | 多轮 SFT 有没有让模型真的用上反馈 |
| `turn_adv_nonzero` | **> 30% 的步数** | 轮级优势是否真的产生了信号 |
| `zero_var_ratio` | 明显低于 0.615 | 多轮 + 轮级优势应该把"全对组"也变成有梯度 |
| `mask_mismatch` | 0 | 与之前一样 |

### 7.4 消融（同一张卡顺带做，约 40 min）

```bash
# beta=0 = 完全退化成 outcome-only，与 7.3 只差一个参数
python -m training.train_grpo --config configs/train/grpo_bird_turn.json \
    --init-adapter runs/sft_bird_p6/adapter --model /root/autodl-tmp/qwen3-4b \
    --out runs/grpo_bird_turn_b0 --kl-beta 0
```

（`turn_beta` 目前走配置文件；做消融时复制一份 config 把 `turn_beta` 改 0 即可。）

### 7.5 评测（约 35 min）

```bash
for tag in turn turn_b0; do
  python scripts/run_baseline.py --dataset bird --backend hf \
      --adapter runs/grpo_bird_$tag/adapter --model-path /root/autodl-tmp/qwen3-4b \
      --turns 1 --stride 5 --timeout 10 --tag bird_${tag}_t1_s5
  python scripts/run_baseline.py --dataset bird --backend hf \
      --adapter runs/grpo_bird_$tag/adapter --model-path /root/autodl-tmp/qwen3-4b \
      --turns 3 --until-correct --stride 5 --timeout 10 --tag bird_${tag}_t3_s5
done
python scripts/reeval_results.py results/baseline_bird_turn_*.json
```

**判读**：
- 轮级 vs beta=0 的 t1 差值 **≥ +2pp** 且 `turn_adv_nonzero` > 30% → P6 成立；
- 只涨 t3 不涨 t1 → 说明学到的是"修复"而不是"一次做对"，也是可写的结论；
- 两者都≈0 → 先把 `turns_mean` 贴出来：如果还是 1.0，说明多轮 SFT 没起作用，问题在数据不在优势。

## 附：常见报错 → 处理

| 报错 | 原因 | 处理 |
|---|---|---|
| `ValueError: too many dimensions 'str'` | transformers 5.x 的 `apply_chat_template` 返回 BatchEncoding | 已修（`chatfmt._as_id_list`），拉最新代码即可 |
| `CUDA out of memory`（SFT） | max_len 3072 + batch 2 | `batch_size=1`、`grad_accum=16` |
| `CUDA out of memory`（GRPO） | G=4 的长轨迹 | `micro_batch=1`，或把 `max_new_tokens` 降到 192 |
| `gold_error` 比例高 | timeout 太小 | 确认 `--timeout 10` |
| 评测 EA 异常高（>80%） | `max_rows` 太小造成假阳性 | 确认 `--dataset bird`（默认 20000 行） |
