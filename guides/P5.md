> 目标：拿到**第一个"RL 比 SFT 好"的证据**。
> 预算：约 **3 小时 GPU / ¥7**（校准 40 min + 训练 2 h + 评测 30 min）。
>
> 前提：P4 的 SFT adapter 还在数据盘上（`runs/sft_qwen3_4b/adapter`），模型还在 `/root/autodl-tmp/qwen3-4b`。

## 0. 为什么 P5 的第一步不是训练

P4 冒烟测到 `zero_var_ratio = 0.90`：训练集 reward 0.95，G=4 时 90% 的组"全对或全错"，
组内优势恒为 0，**90% 的采样对参数更新零贡献**。

直接上 300 步 = 花 ¥5 看 loss 在 0 附近抖动。所以顺序是：

```
① 校准（找出 0.2 < p < 0.8 的题） → ② 训练（只喂这些题） → ③ 评测（对比 SFT 的 78/87）
```

## 2. 校准 pass-rate（约 30~45 分钟）

```bash
cd /root/autodl-tmp/sql-agent-rl
export PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True

python scripts/calibrate_rl_prompts.py \
  --difficulty hard,extra \
  --group-size 4 \
  --adapter runs/sft_qwen3_4b/adapter \
  --model /root/autodl-tmp/qwen3-4b
```

它做的事：对 hard/extra 的 **396 条** prompt 各采 4 条轨迹，算每题通过率 p。

- 每 10 条打一行进度，**中断后重跑同一条命令会续跑**
- 输出 `data/train/rl_calibrated.jsonl`（全部 p）和 `data/train/rl_p5_train.jsonl`（筛出来的）

**跑完看这一段**：

```
校准 396 条  |  p 均值 0.6xx 中位数 0.6xx
全对 xxx 条 / 全错 xx 条 / 有信号区间内 xxx 条 (xx%)
按 G=4 估算的零方差比例（校准集上）：0.xx
筛选集难度分布：{'hard': ..., 'extra': ...}
```

**判读**：

| 结果 | 怎么办 |
|---|---|
| 筛出 **≥120 条** | 理想，直接进第 3 步 |
| 筛出 **50~120 条** | 可用，但把 `--p-low` 降到 0.1 能多捞一些；训练步数按比例降（如 200 步） |
| 筛出 **<50 条** | **不要训**。改成校准全量 `--difficulty all`，或直接跳到 P6 的分层奖励 |

## 5. 结果怎么判

对照 P4 的 SFT（**78.00% / 87.00%**）：

| 结果 | 判定 | 下一步 |
|---|---|---|
| t1 > 78 且 t3 > 87 | ✅ **RL 有增益**，主表成立 | 重复 2 个 seed，写进报告 |
| t3 > 87 但 t1 掉了 | 模型学会了"靠多轮补救"，单轮变弱 | 也算正结果，但主表要讲清机制 |
| 都没涨，但 zero_var 明显下降 | 训练机制对了，信号不够/步数不够 | 加步数或加 G，再跑一次 |
| 明显下降（>3pp） | 过度更新 / KL 太弱 | 降 lr 到 1e-6、KL 提到 0.04 |
| zero_var 仍 >0.8 | 校准没生效（可能读了旧文件） | 检查 `[数据]` 那行打印的 p 均值 |

**验收标准**：主表要有 **5 行**——DeepSeek-chat、4B-Base（可选）、SFT-t1、SFT-t3、GRPO-t3。

## 8. Plan B：校准筛不出题时，用"轮级塑形奖励"

**触发条件**：校准 100 条后，`0.1 < p < 0.9` 的题不足 60 条，或 `全对` 超过 70%。

### 为什么塑形奖励能救

模型准确率 ~86% 时，outcome-only 的组里绝大多数"全对"，组内优势 = 0。
但如果奖励里带上**轮数**：一轮解出得 1.0、两轮 0.9、三轮 0.8，那么
即使四条轨迹全对，组内也有方差：

```
rewards = [1.0, 1.0, 0.9, 0.8]  →  std > 0  →  优势 ≠ 0  →  有梯度
```

配置 `configs/train/grpo_p5_dense.json` 已经写好：

- `reward_turn_penalty = 0.1`（每多用一轮扣 0.1）
- `reward_first_turn_bonus = 0.1`（一轮解出再加 0.1）

客观目标变成"**用更少的轮数答对**"——这本身就是 agent 效率的核心指标，
而且它是 P6"轮级信用分配"的天然前奏。

### 命令（不用再校准）

```bash
python -m training.train_grpo \
  --config configs/train/grpo_p5_dense.json \
  --init-adapter runs/sft_qwen3_4b/adapter \
  --model /root/autodl-tmp/qwen3-4b
```

`rl_file` 是 `rl_train.jsonl`（全量 1500 条），不需要筛选——因为方差来自轮数，不来自对错。

### 需要额外上传的文件

```
training/rollout.py     （新增 turn_penalty / first_turn_bonus）
training/config.py      （两个新配置项）
training/train_grpo.py  （把参数传进 reward）
configs/train/grpo_p5_dense.json
```

### 验收标准（与 Plan A 不同）

| 指标 | 要求 | 含义 |
|---|---|---|
| `zero_var_ratio` | **< 0.3** | 塑形生效的直接证据 |
| `turns_mean` | 逐步下降 | 模型在学"少绕弯" |
| `reward_mean` | 0.85 左右（略低于 1.0） | 说明轮数扣分起作用了 |
| dev `t3` EA | 不低于 87.0 − 1pp | 效率提升不能以正确率为代价 |
| dev `t1` EA | 可能上升 | 一轮就对的题变多 |

> 这个实验的结论句会更硬：「在 outcome-only 无信号（零方差 0.90）的情况下，
> 引入轮级塑形后零方差降到 X，且 dev 首轮通过率提升 Y pp」。

## 9. 常见问题

> **KL 必须设 0（重要）**：`adapter_disabled()` 关掉的是**所有** LoRA，所以 KL 的参考策略是
> **基座模型**而不是 SFT 后的策略。从 SFT adapter 起步时，实测 KL 高达 1.7~2.6——
> 每步都在把模型往"未 SFT"的方向拉，会持续摧毁 SFT 能力。
> 正确做法：`kl_beta = 0`；若确实需要锚点，得另存一份冻结的 SFT adapter 作参考策略。

| 现象 | 原因 | 处理 |
|---|---|---|
| 校准脚本报 `FileNotFoundError: data/raw/spider/database` | 数据没同步 | P4 的 160 个 sqlite 还在数据盘上，检查路径 |
| 训练时 `[数据] RL prompt 1500 条` | 读到了旧的 `rl_train.jsonl` | 确认配置里 `rl_file` 是 `rl_p5_train.jsonl`，或加 `--rl-file` |
| `reward_mean` 一直是 1.0 | 校准文件没换 / p 全等于 1 | 看 `[数据] 校准 p 均值` 那行 |
| 训练到一半机器被停机 | 余额不足 | 数据不丢，充钱开机后 `--steps` 剩多少不确定，建议整轮重跑（有 `save_every` 的 adapter 可作参考） |
