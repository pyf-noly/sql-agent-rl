## 6. SFT 冷启动

```bash
python -m training.train_sft --config configs/train/sft_qwen3_4b.json
```

预计 30~50 分钟，日志长这样：

```
[参数] 总 4.0B，可训练 40.4M (1.01%)
[数据] train 2369 条 / val 205 条
[数据] {'length': {'mean': 390.2, 'p95': 640, ...}, 'context_ratio_mean': 0.31, 'n_mismatch': 0}
[   5/334] loss 1.8421  lr 1.20e-04  显存 15.8G  12.4s
...
[done] val_loss 0.4123，adapter 存到 runs/sft_qwen3_4b/adapter
```

**验收标准（三条都要）**：

1. `loss` 从 ~2.0 降到 ~0.5 以下（SFT 是模仿学习，loss 应该明显降）；
2. `n_mismatch = 0`；
3. `显存 < 22G`（超了就是 batch/长度配置问题，别硬扛）。

> `context_ratio_mean ≈ 0.3` 意思是"30% 的 token 是 schema 和工具反馈"。
> 这个数说明多轮训练的代价，P6 讨论效率时要引用它。

## 7. 评测 SFT 模型（**P4 最重要的数字**）

```bash
# 单轮（对应 B1 的设置，公平对比）
python scripts/run_baseline.py --backend hf --split full --turns 1 \
    --adapter runs/sft_qwen3_4b/adapter --tag sft_t1

# 三轮自修复（对应 B2，判对才停）
python scripts/run_baseline.py --backend hf --split full --turns 3 --until-correct \
    --adapter runs/sft_qwen3_4b/adapter --tag sft_t3
```

各 20~30 分钟。跑完你会得到两张表：`results/baseline_sft_t1.json` / `_t3.json`。

**把这两个数字对照这张表**（来自 `docs/p2_decision.md`）：

| 4B-SFT 单轮 EA | 判断 | 下一步 |
|---|---|---|
| 55~70% | 理想 | 照原计划做 P5（GRPO） |
| 40~55% | 可行 | 加 SFT 数据/epoch，再评一次 |
| > 75% | 偏简单 | 主表只报 hard/extra，或加 CoT |
| < 40% | 偏难 | 先查是不是格式问题（看 `pred_error` 计数） |

**先别急着跑 GRPO**：如果 `t3 - t1 < 3pp`，说明这个模型"不会利用反馈"，
P6 的轮级优势就没有着力点——那时候要先改任务/模型，而不是加训练量。

## 8. GRPO 冒烟（20 步，只验证循环能跑）

```bash
python -m training.train_grpo --config configs/train/grpo_smoke_4b.json \
    --init-adapter runs/sft_qwen3_4b/adapter
```

预计 10~20 分钟。日志：

```
[  1/20] reward 0.25 零方差 50% | loss -0.0210 | 轮数 1.8 | 显存 18.3G | 40.2s
...
[done] 20 步，78 条轨迹，耗时 900s
```

**验收标准（这是 P4 的硬指标，我按这个检查）**：

| 指标 | 要求 | 不正常意味着 |
|---|---|---|
| `mask_mismatch` | **恒为 0** | 模板/拼接有问题，梯度是错的 |
| `ratio_mean` | **恒为 1.0** | 不是 1 说明老策略 logp 算错（单步更新应为 1） |
| `zero_var_ratio` | < 0.8 | 太高 = 奖励没区分度（全对/全错），训练学不到东西 |
| `显存` | < 22G | 超了要降 `group_size` 或 `max_len` |
| `reward_mean` | 第 20 步 ≥ 第 1 步（允许震荡） | 完全不涨说明优势或 mask 有问题 |

**`ratio_mean` 为什么必须是 1.0**：每条样本只更新一次就丢掉，算 loss 时权重
没变过，所以 `exp(logp_new - logp_old) ≡ 1`。如果它不是 1，说明你在用**更新后**的
权重去算"老策略"的 logp，这是 RL 里最典型的静默 bug。

## 10. 常见报错对照表

| 报错 | 原因 | 处理 |
|---|---|---|
| `CUDA out of memory`（SFT） | batch 太大 | `--batch-size 1`，或把 `max_len` 降到 1536 |
| `CUDA out of memory`（GRPO） | group_size 太大 | `--group-size 2`，或 `max_new_tokens` 降到 128 |
| 下载卡在 `Loading checkpoint shards` | 没用镜像站 | 确认 `HF_ENDPOINT=https://hf-mirror.com` 已 export |
| `KeyError: 'q_proj'` / target_modules 不存在 | 模型结构不同 | 查 `model.named_modules()`，改 `lora_targets` |
| `RuntimeError: element 0 of tensors does not require grad` | LoRA + 梯度检查点没开 input grad | 已内置 `enable_input_require_grads()`，若仍报错检查 peft 版本 |
| `tokenizer.chat_template is not set` | 模型不是 instruct 版 | 换 `Qwen3-4B-Instruct-2507` |
| 生成全是乱码/不闭合 ```` ```sql ```` | 用了 base 模型 | 同上；SFT 后再看 |
| `check_p4_env.py` 里 mask mismatch > 0 | 模板版本差异 | 把 `report.json` 发我，别硬训 |
