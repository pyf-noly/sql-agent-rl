# 面试问答：10 个必被问的问题

> 用法：`README.md` 是投屏材料，这份是**被追问时的口径**。
> 每题的结构：一句话答案 → 展开（带项目里的数字/代码位置）→ 继续追问时怎么答。
> 原则：不吹"显著提升"，所有数字都能在 `results/*.json` 里复算。

## Q1. 为什么"状态"不是当前这轮的 SQL，而是完整历史？

**一句话**：因为错误反馈改变了后验，下一步动作取决于"模型已经试过什么、看到过什么"，
这是典型的 POMDP——只看当前 SQL 会丢掉"上一轮为什么错"。

**展开**：

- 我们的 `SqlAgent`（`rollout/agent.py`）把每轮回灌的反馈**作为消息保存**
  （`Turn.feedback_message`），下一轮 prompt 是 `history + assistant(上一轮 SQL) + user(反馈)`；
- 一个直接证据：同一个错误 SQL，在一次尝试里是"第一次写错"，在另一次里是"改了两轮还错"，
  两者该给的修正动作完全不同；
- 训练侧也强制一致：SFT/GRPO 的序列由 `messages_from_episode` 从保存的 messages **原样重建**，
  不是另拼一套模板——否则训练和推理会静默分叉（P4 踩过：SFT 数据缺 system/schema，
  与推理分布不一致）。

**继续追问**："那状态空间不是无限大？" → 是，所以用固定轮数（≤3）+ 反馈截断（~120 token）
+ max_len 2560 把它压到可训练的范围；长度控制见 Q6。

## Q2. 轮级优势具体怎么算？单样本轮、无方差轮怎么办？

**一句话**：按"第一次做对发生在第几轮"给每个轮次位置一个 0/1 标签，逐轮在组内标准化，
再与整条轨迹的优势相加；**某一轮组内全同就置 0**（没方差就不给梯度）。

**展开**（`training/grpo.py:84-159`）：

```python
y[i,t] = 1                     # 轨迹 i 第一次做对在第 t 轮（没做对则全 0）
A_turn[i,t] = (y[:,t] - mean_t) / std_t        # 逐轮次、组内标准化
A[i,t] = A_ep[i] + beta * A_turn[i,t]          # 相加，beta=0 退化成 outcome-only
loss = -min(ratio*A, clip(ratio)*A)            # token 级
```

三个边界情况，都是刻意设计的：

1. **某一轮组内全同**（例如 4 条全在第 1 轮做对）：`std_t=0` → `A_turn[:,t]=0`。
   不除以 `1e-6` 把浮点噪声放大成信号；
2. **轨迹提前结束**：训练时 `stop_on_correct=True`（`training/rollout.py:97`），
   做对就停，所以"一轮解出"的轨迹只有 1 轮 token。它在第 1 轮拿到 `+`，
   而"第三轮才改对"的轨迹在第 1/2 轮拿 `−`、第 3 轮拿 `+`——
   **这不只是"越快越好"，同时也在惩罚错误的尝试、奖励改对的那一次**；
3. **β=0 严格退化**：`combine_advantages` 是加法，β=0 时逐 token 优势恒等于
   `A_ep`，和 P5 的 outcome-only 完全一致——所以消融不需要两份代码。

**和 GiGPO / step-level 的区别（会被问）**：我们用"轮次下标"对齐，GiGPO 用 anchor state
对齐。前者便宜但粗——第 3 轮的两个状态未必可比；实测 `turn_adv_abs_mean` 0.34（与 outcome
同量级），`turn_adv_nonzero` 59%，说明它确实在产生信号，但没有做状态对齐是它的上限。

## Q3. 怎么发现 reward hacking 的？

**一句话**：不是靠肉眼看 loss，而是先定义"如果模型作弊，哪个指标会动"，再把它做成
每步都打印的指标。

**展开**：

1. **格式作弊**（只输出合法 SQL 骗格式分）：奖励里对解析失败给 **−0.2**，
   而不是 0，避免"乱写也有分"；每步记录 `parse_error`；
2. **空查询作弊**（`WHERE 1=0` 拿"执行成功"）：`empty_result` 是独立错误类
   （`envs/error_taxonomy.py`），反馈会明确说"0 行，检查 WHERE/JOIN"；
   评测里 `pred_error` 与 `empty_vs_empty` 分开计数（`rollout/evaluator.py:76-83`）；
3. **训练 reward 涨但 EA 不涨**：这是最危险的一种。我们的对照方式是把
   `reward_mean`、`zero_var_ratio`、`clip_frac` 与离线 EA 放在同一条日志里看
   （`training/train_grpo.py`，P6 的 `turn_adv_nonzero` 也是这么加的）；
4. **答案泄漏**：反馈里绝不能出现 gold SQL 或正确结果，有 3 组参数化测试
   （`tests/test_error_taxonomy.py:125-137`）；评测器只用于"判对才停"的停机决策，
   不进入反馈（`rollout/agent.py:137-139`）。

**诚实补充**：没有做完整的 reward-hacking notebook（原计划 P7 的 `analysis/` 那套），
但指标体系留了口子；如果要补，第一步是统计"合法但空查询"的比例随步数的变化。

## Q4. 为什么用 GRPO 不用 PPO？

**一句话**：PPO 要一个和策略同规模的 critic，在长轨迹上既难训又吃显存；
GRPO 用组内相对值当基线，省一个模型，代价是"全对/全错组没有信号"。

**展开**：

- 我们的场景是单卡 24G 跑 4B + LoRA，LoRA 可训练参数 33M；
  再挂一个 critic 直接吃满显存，而且多轮轨迹的 value 估计方差极大；
- **GRPO 的失效条件我知道**：组内奖励全同 → 优势 0 → 该步零梯度。
  P4 实测 `zero_var_ratio=0.90`，P5 最低 0.74，BIRD 0.615——这三组数字是同一个现象的
  三个难度；
- 所以我们没有"加大 G"或"调温度"去硬救，而是换数据（P6）+ 改优势结构（轮级）。

**继续追问**："那你为什么不用 Dr. GRPO（去掉 std 归一化）？"
→ `group_advantages(normalize=False)` 已经实现了（`training/grpo.py:44-62`），
只是这轮实验没跑这个消融；std 归一化在"全对组"上会把 `1e-6` 放大，我们是用
`where=std>1e-4` 直接置 0 规避的。

## Q5. 异步 rollout 的样本陈旧问题怎么处理？

**一句话**：这一版**没有做异步**——单卡同步采样、1 个 inner epoch，所以 `ratio ≡ 1`，
不存在 off-policy 修正；这是有意的简化，不是遗漏。

**展开**：

- 训练循环是：同一组 4 条轨迹 → 算优势 → 立刻更新（`training/train_grpo.py`），
  日志里 `ratio_mean` 恒 1.0 就是证据（一条轨迹只用一次，on-policy）；
- 代价是吞吐低：4090 上 **200 步约 50 分钟**；收益是实现简单、没有 importance ratio 的坑；
- 如果要做异步（vLLM/SGLang 后端），必须补：`old_logp` 用采样时策略算、
  按 token 做 importance correction、限制单条样本的陈旧步数（staleness cap）。
  这些在自研框架里是 2~3 天的工程量，对本项目的结论没有增量，所以没做。

## Q6. 多轮 rollout 的长度爆炸怎么控制？

**一句话**：四道闸——最大轮数 3、每轮 `max_new_tokens=256`、反馈截断（~120 token）、
序列 `max_len 2560`；外加"代码块闭合早停"，把生成时间从 21s/题压到 3.7s/题。

**展开**：

| 闸门 | 值 | 副作用 |
|---|---|---|
| `max_turns` | 3 | 超过 3 轮的修复学不到（BIRD dev 的 prompt p95 ≈1865 token） |
| `max_new_tokens` | 256 | 太短会截断长 SQL；实测 BIRD 的 SQL 很短，够用 |
| 反馈截断 | 500 字符（`to_dict`）/ 模板本身 ~120 token | 长反馈会被砍，但 schema 提示只列相关表 |
| `max_len` | 2560 | 3072 在多轮 SFT 上 OOM（`Tried to allocate 2.57 GiB`） |
| 早停 | `_FenceStop`（``` 闭合即停） | 9 成时间花在代码块外的解释文本上 |

**继续追问**："长度惩罚呢？" → P5 试过"每多一轮 −0.1"的塑形奖励，
把零方差从 10% 提到 26%，但最终增益仍在噪声内；P6 改用轮级优势后不再需要它。

## Q7. 为什么 4B 模型能出结论？

**一句话**：因为结论是**机制层面**的（零方差、信用分配、反馈信息量），不是"我们刷到了 SOTA"；
而且所有对照都在同一批样本上做配对检验，不靠绝对分数说话。

**展开**：

- 4B 在 BIRD 零样本 49.8%，正落在 GRPO 需要的 p≈0.5 区间——这是**选它做实验**的理由，
  不是"它够强"；
- Spider 上 4B-SFT 已到 78%/87%，零方差 0.74~0.90，说明这个任务对 4B 已经饱和——
  这正是"换数据"的实验结论；
- 所有 BIRD 数字都是 n=307、单 seed，+2.93pp 的配对 p=0.27，**报告里明确写"不显著"**。

**继续追问**："那你的结论能推广到 7B/32B 吗？" → 零方差和反馈信息量这两个机制
与模型规模无关（反馈里没有信息，再大的模型也改不对），但"轮级优势的收益"可能随规模
下降（大模型更容易一次做对，过程分化更少）。这是可检验的假设，不是已证结论。

## Q8. 如果给你 8 卡一个月，下一步做什么？

**一句话**：先补信息的多样性，再补规模——优先级是"跨查询自洽检查 > 全量/多 seed >
更大基座 > tree search"。

**展开**：

1. **跨查询自洽检查**（最优先）：现在只有"值存在性"一种语义检查。可以加
   "同一问题多条 SQL 的结果是否一致"、"聚合列是否在 GROUP BY 里"等结构检查，
   把可检测错误从 10%~21% 往上提——§6.3 的结论说这是自修复的上限；
2. **全量 + 多 seed**：BIRD dev 1534 条、3 seeds，把 +2.93pp 的 CI 收窄
   （按当前效应量，80% 功效约需 1577 条）；
3. **更大基座**（8B/14B）：验证"轮级优势的收益随规模下降"这个假设；
4. **tree search / GiGPO**：做状态对齐的 step-level 优势，替代现在粗粒度的"轮次下标"；
5. **环境扩展**：把同一套"只读沙箱 + 结构化反馈"搬到代码执行/终端任务，
   验证"反馈信息量决定上限"是不是更普适。

**继续追问**："为什么不是先加 GRPO 步数？" → 已经证过：BIRD 上 200 步 outcome-only
是 ±0.0pp，再加步数只是把同样的信号重复一遍；瓶颈在信号，不在步数。

## Q9. 两种评测口径有什么区别？为什么要两个？

**一句话**：`rows` 是我们从 P2 用到 P5 的宽松口径（行数敏感、列序不敏感、数值归一化），
`bird` 是 BIRD 官方口径（原始元组集合比较）；前者用于和自己历史表对齐，后者用于和论文对齐。

**展开**：

| | `rows` | `bird` |
|---|---|---|
| 行数 | 必须一致 | 不直接比（集合比较） |
| 列顺序 | 不敏感 | 敏感 |
| 数值归一化 | `1 == 1.0 == "1"` | 不做 |
| 重复行 | 敏感 | 忽略 |
| 空结果 | 双方都空判对（记 `empty_vs_empty`） | 集合相等即对 |

实测同一批 BIRD 数据：官方口径 49.8%、`rows` 口径 46.1%，差 3.7pp。
**只报一个都不诚实**，所以 README 里两个口径都写清楚用在哪。

**继续追问**："为什么不直接用官方 test-suite？" → 官方 test-suite 是给 Spider 的；
BIRD 的官方 evaluator 我们按它的 `set` 语义实现了（`rollout/evaluator.py:155-191`），
剩下的差异是超时/类型处理细节。Spider 侧确实应该用官方 test-suite 复核主表，
这是 P7 没做完的（本地 4-bit 约 40 分钟，¥0）。

## Q10. +2.93pp 不显著，为什么还值得写？

**一句话**：因为它的价值在**机制**和**负结果的归因**，不在那个小数点；
而且"不显著"本身是量化过的（p=0.272、CI [−1.72, +7.58]），不是一个形容词。

**展开**：

- 这份工作的可迁移部分是：① 零方差必须实测（均值估算高估 5 倍）；
  ② 轮级优势的正确用法与它的上限（只在"全对组"里有信号）；
  ③ **反馈信息量决定自修复上限**——这条是三个独立实验交叉验证的；
- 唯一显著的结论是"多轮比单轮好"（+5.21pp，p<0.001），它支撑了"多轮环境值得做"这个前提；
- 负结果（outcome-only 在 BIRD 上 ±0.0pp、强模型改错只有 10%）写进报告，
  因为下一个做这件事的人会先试这两条路。

**继续追问**："那你觉得这个项目最大的问题是什么？" →
样本量（n=307、单 seed）和"没有做官方 test-suite 复核"。
前者是钱的问题（全量 + 多 seed 约 ¥10），后者是时间问题；
两个都不影响机制结论，但会影响"能不能写进论文"。

## 附录：三个更尖的追问

**① "你的轮级优势是不是就是把 episode 优势按轮拆了一下？"**
是，但拆的方式有讲究：`y` 是"**第一次**做对"的 one-hot，不是"这一轮是否做对"。
区别在于：如果一条轨迹第 2 轮做对、第 3 轮又做错（理论上 stop_on_correct 不会发生），
用"是否做对"会重复计分。我们只认第一次。

**② "为什么不用 process reward model？"**
PRM 需要过程标注，而我们的环境只能给"结果对不对"+"错误类型"；
用规则塑形（P5）试过，零方差从 10% 到 26% 但分数没动。规则塑形的上限就是"人能把过程
写清楚"，而轮级优势是"从结果里自己学出过程"，这是更符合本项目约束的路线。

**③ "如果重做一遍，你会改什么？"**
三件事：① 一开始就做库级切分（P5 才发现训练库已被 SFT 覆盖，任何奖励设计都救不了）；
② 多轮数据从第一天就 mask 第一轮（v2 的 4.6pp 是白交的学费）；
③ 所有对照从第一天就用配对检验，而不是等 P7 才发现 SE 高估了 1.7 倍。
